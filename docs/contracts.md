# Contracts and schemas

The authoritative definitions are the Pydantic models in `src/sra/models.py`. Committed JSON Schemas use draft 2020-12 and are generated by `sra schema all --output-dir schemas`. `--check` detects drift. Do not hand-edit generated schemas.

## Contract inventory

| Schema | Purpose | Producer → consumer |
|---|---|---|
| `workflow.schema.json` | Trusted project configuration | Repository owner → coordinator |
| `workspec.schema.json` | One bounded research task | Planner/operator → approval and runner |
| `capabilities.schema.json` | Observed CLI surfaces | Provider adapter → doctor/run log |
| `agent-event.schema.json` | Stable normalized telemetry | Adapter → event log |
| `run-record.schema.json` | Execution ownership, state, typed evidence | Coordinator → SQLite/CLI |

All public models reject unknown top-level fields. Provider-native metadata in `AgentEvent.data` and usage objects is intentionally extensible. `schema_version` is 1 for the first release; unsupported versions are rejected. This is separate from CLI version compatibility.

## Workflow

`WORKFLOW.md` contains YAML front matter followed by Markdown execution instructions. Duplicate YAML keys, non-string mapping keys, malformed front matter, and undefined required checks are rejected.

```yaml
---
schema_version: 1
tracker:
  repository: OWNER/REPO
  token_env: GITHUB_TOKEN
  ready_label: agent-ready
base_ref: main
planner:
  provider: claude
executor:
  provider: codex
runners:
  codex:
    command: [codex]
    codex_network_access: false
  claude:
    command: [claude]
checks:
  unit:
    argv: [python, -m, pytest, -q]
    timeout_seconds: 900
required_checks: [unit]
limits:
  max_concurrent_runs: 1
  max_attempts: 3
---

Follow the approved spec. The host owns validation and delivery.
```

`command` and `argv` are argument arrays, never shell strings. A configured wrapper may prefix the actual binary, for example `command: [mise, exec, --, codex]`. Such wrappers are trusted code.

`model` and `effort` are optional native identifiers. They are not globally enumerated. Changing provider never forwards the previous provider's model name. Precedence is explicit run override → selected WorkSpec/project selection → provider defaults → native CLI defaults. Planning has a separate selection.

Checks are host-owned commands. The executed set is the union of `required_checks` and `WorkSpec.check_ids`; a spec cannot remove project-required checks. No check argv is accepted from a remote Issue. The initial project template has no checks; configure them before relying on automated evidence.

The policy digest includes normalized configuration, the workflow prompt, and the contents of present root `AGENTS.md`, `CLAUDE.md`, `.agent/POLICY.md`, and `.agent/PLANNING.md`. It is not a complete digest of every provider setting, nested instruction file, external dependency, or user HOME configuration.

## WorkSpec

The following fields define a work contract:

| Field | Meaning |
|---|---|
| `id`, `revision` | Stable task ID and monotonically increasing revision for changed content |
| `title`, `objective`, `kind` | Task identity and research intent |
| `scope.include`, `scope.exclude` | Allowed delivery paths, not OS access control |
| `acceptance[]` | Unique criterion ID, description, and observable evidence requirement |
| `check_ids` | References to trusted project checks |
| `non_goals`, `stop_conditions` | Explicit limits and escalation conditions |
| `research` | Hypothesis, dataset references, seeds, metrics, artifact paths |
| `execution` | Optional per-task provider/model/effort selection |
| `delivery` | `draft_pr` or `report` |

See [the complete example](../examples/workspec.json).

Path patterns use Python `fnmatchcase` against repository-relative POSIX paths. In particular, `*` may match `/`; this is not Git's ignore/pathspec semantics. Absolute paths, `..` components, backslashes, and `.git` paths are rejected in scope/artifact path declarations.

Default protected paths include workflow/instruction files, `.agent/*`, `.github/*`, and common secret filenames. The generated `docs/specs/<id>.md` is a special host-written projection and must remain byte-for-byte equal to the approved contract. Changes to symlinks, submodules/directories, escaping paths, and oversized changed files are not supported for delivery.

The guards inspect changes after execution and before delivery. They do not stop a malicious process from reading or writing arbitrary host files while it runs.

## Issue and Markdown authority

An Issue stores one JSON block between `<!-- sra:workspec:v1 -->` and `<!-- /sra:workspec -->`. This block is canonical. Its SHA-256 is computed from validated, normalized JSON with sorted keys and compact separators; comments and human-readable projections are not hashed.

The Issue includes readable Markdown plus a collapsed machine block. The workspace contains `docs/specs/<id>.md`, generated from the same object. This solves the bootstrap problem: the agent can start from an approved Issue before its Markdown file exists in a PR.

Edit a draft JSON file, increment revision, and republish to change the contract. Editing the readable prose alone does not change the executable contract. Editing the canonical JSON invalidates local approval until the new digest is approved.

## Approval

An approval binds `(repository, issue_number, spec_id, revision, spec_sha256, policy_sha256)` in local SQLite. An `agent-ready` label is an eligibility hint, not authorization. Only the local operator creates approvals. The watcher ignores unapproved remote work.

There is no approval synchronization between hosts. Sharing only Issues does not share runtime authorization. Publication is idempotent under sequential use and locally serialized in one state root, but no global exactly-once GitHub guarantee is claimed.

## AgentEvent

Normalized types are `session.started`, `progress`, `tool`, `usage`, `completed`, `failed`, and `diagnostic`. Events include timestamp, provider, optional native type, optional native session ID, optional text, and extensible metadata.

Native stderr and unmapped events become diagnostic records. Unknown telemetry does not terminate a successful run. Required terminal events still matter. Token counts not supplied by a provider remain absent; SRA does not fabricate comparable cost or effort figures.

## RunRecord and evidence

A run records repository/Issue, spec/policy hashes, attempt number, selection, workspace/branch/base SHA, host/PIDs, timestamps, native session ID, state, optional error and PR URL, and typed `RunEvidence`.

Evidence includes check results, changed files, a content fingerprint, reported usage, observed CLI version, verification time, optional delivered commit SHA, and `human_acceptance_required: true`.

The fingerprint binds the originally recorded base SHA to changed file contents and modes. It is checked before and after commit; the pushed ref names the verified commit SHA, not an unchecked later `HEAD`. External concurrent mutations are unsupported; checks still reduce accidental stale-result publication.

## Database

SQLite uses `PRAGMA user_version=1`, WAL mode, transactions, a unique active-run index, and compare-and-set delivery transitions. Unknown future database versions are refused rather than silently reinterpreted.

Changing these contracts requires migration fixtures and schema tests. Keep older state backups before upgrading experimental releases. CLI version tolerance is not a reason to disable application schema or permission validation.
